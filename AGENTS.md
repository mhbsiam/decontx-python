# AGENTS.md - decontx-python development guide

## Environment

- **Python env**: `conda run -n scrna_v2 python ...` (has numpy, scipy, numba, scanpy, anndata)
- **Install for editable local dev**: `conda run -n scrna_v2 pip install -e . --no-deps`
- **Run tests**: `conda run -n scrna_v2 python -m pytest tests/test_core.py tests/test_regression.py -v -o addopts=""`
  - `addopts=""` overrides the pyproject.toml pytest-cov requirement.
- **Run benchmark**: `PYTHONPATH=. conda run -n scrna_v2 python tests/benchmark.py`
- **Head-to-head compare**: `PYTHONPATH=. conda run -n scrna_v2 python tests/benchmark_compare.py`
- **Regenerate golden reference**: `conda run -n scrna_v2 python tests/generate_golden.py`
- **Ruff lint**: `conda run -n scrna_v2 ruff check .` (notebooks excluded)
- **Ruff format check**: `conda run -n scrna_v2 ruff format --check .`

## Validation workflow (CRITICAL)

All performance optimizations MUST pass the regression gate before shipping:

1. **Golden reference** in `tests/golden/` was generated by `tests/generate_golden.py`
   using the original dense implementation on a fixed synthetic dataset
   (400 cells x 300 genes, 4 clusters, 17.4% density).

2. **Regression tests** in `tests/test_regression.py` enforce:
   - `test_regression_*_bit_identical`: theta, phi, eta, contamination, decontX_counts
     must match golden to atol=1e-8 (bit-identical for safe optimizations)
   - `test_regression_correlation_gate`: contamination correlation with golden
     must be > 0.999 (the scientific accuracy gate, always required)

3. **After any change to fast_ops.py or model.py**:
   - Clear Numba cache: `find . -name "__pycache__" -type d -exec rm -rf {} +; find . -name "*.nbc" -delete; find . -name "*.nbi" -delete`
   - Run: `conda run -n scrna_v2 python -m pytest tests/test_core.py tests/test_regression.py -v -o addopts=""`
   - All 7 tests must pass

4. **When to regenerate golden**: only if the algorithm itself changes (not just
   performance). Re-run `tests/generate_golden.py` and verify the new golden
   matches the R reference correlation > 0.999.

5. **Multi-batch smoke test**: run `decontx(..., batch_key=...)` on a dataset with
   multiple batches and non-sequential per-batch cluster labels; must not crash.

## Architecture

- `decontx/core.py`: user-facing `decontx()` function, AnnData integration
- `decontx/model.py`: `DecontXModel.fit_transform()` — the EM loop
  - All input is converted to CSR (never densified during EM)
  - Pre-allocates `nc_data` (1D, length nnz), `phi_acc` (n_clusters, n_genes),
    `native_sums` (n_cells), and `global_acc` (n_genes); all reused each EM iteration
  - Calls `decontx_em_exact_sparse` (monolithic JIT: E-step + M-step)
  - Output is a sparse CSR matrix (same sparsity pattern as input)
- `decontx/fast_ops.py`: Numba JIT functions
  - `decontx_em_exact_sparse`: monolithic sparse EM (E+M in one JIT call)
    - E-step: parallel `prange` over cells, fills `nc_data` (CSR-aligned 1D)
    - M-step: serial scatter-add from `nc_data` into `phi_acc`, then normalize
  - `decontx_initialize_exact_sparse`: sparse-aware phi/eta initialization
  - `calculate_native_matrix_fast_sparse`: final decontaminated counts (CSR-aligned)
  - `decontx_log_likelihood_exact_sparse`: sparse log-likelihood
  - `decontx_em_exact`: original dense EM (legacy, not used in sparse path)
  - `precompile()`: opt-in JIT precompilation (lazy, not import-time)

## Optimization decisions and safety notes

1. **CSR-aligned nc_data**: `native_counts[j,g]` is 0 when `counts[j,g]==0` (the
   original code already guards with `if counts[j,g] > 0`). Keeping only the
   nonzero values in a 1D array aligned to CSR positions is bit-identical.
2. **Scatter-add M-step**: `phi_acc[k,g] += nc_data[idx]` accumulates the same
   values in the same order as the dense `np.sum(native_counts[mask, :], axis=0)`.
   The scatter-add iterates cells in order, and within each cell iterates CSR
   nonzeros in order — same summation order as dense row-major iteration.
3. **prange over cells (E-step only)**: each thread writes to disjoint slices of
   `nc_data` (cell j owns indptr[j]:indptr[j+1]). No shared writes. Bit-identical.
4. **eta from global_acc - phi_acc[k]**: `other_native = total_native - cluster_native`
   is algebraically identical to `np.sum(native_counts[other_mask, :], axis=0)`.
   Same values, same float64 arithmetic. Bit-identical.
5. **Pre-allocated EM buffers (`nc_data`, `phi_acc`, `native_sums`, `global_acc`)**:
   pure memory reuse, no arithmetic change.
6. **Lazy JIT compilation**: moved from import-time to first-use. No behavior change.
7. **Division-by-zero guard in eta**: if `total <= 0` (single-cluster edge case),
   falls back to uniform distribution. Bit-identical for normal multi-cluster data.
8. **Division-by-zero guards for theta and delta updates**: protect against small
   denominators when `counts_colsums + delta[0] + delta[1] - 2.0` is near zero
   or `var_prop` underflows. Bit-identical for well-conditioned data.
9. **Cluster label remapping in DecontXModel**: `fit_transform` remaps arbitrary
   input `z` labels to a contiguous `1..n_clusters` range. This makes multi-batch
   processing safe when a batch contains only a subset of the global clusters.
10. **Optional `compute_log_likelihood`**: skipping the log-likelihood kernel removes
    periodic O(nnz) work. Default is `True` for backward compatibility. No accuracy
    impact because log-likelihood is used only for diagnostics/history.
11. **Convergence check stays coupled to `iter_loglik`**: decoupling it (checking
    `theta_change` every iteration) was tested and broke bit-identical regression,
    so it was reverted.
