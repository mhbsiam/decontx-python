# AGENTS.md - decontx-python development guide

## Environment

- **Python env**: `conda run -n scrna_v2 python ...` (has numpy, scipy, numba, scanpy, anndata)
- **Install for editable local dev**: `conda run -n scrna_v2 pip install -e . --no-deps`
- **Run tests**: `conda run -n scrna_v2 python -m pytest tests/test_core.py tests/test_regression.py -v -o addopts=""`
  - `addopts=""` overrides the pyproject.toml pytest-cov requirement.
- **Run benchmark**: `PYTHONPATH=. conda run -n scrna_v2 python tests/benchmark.py`
- **Head-to-head compare**: `PYTHONPATH=. conda run -n scrna_v2 python tests/benchmark_compare.py`
- **Regenerate golden reference**: `conda run -n scrna_v2 python tests/generate_golden.py`
- **Ruff lint**: `conda run -n scrna_v2 ruff check .` (notebooks excluded)
- **Ruff format check**: `conda run -n scrna_v2 ruff format --check .`

## Validation workflow (CRITICAL)

All performance optimizations MUST pass the regression gate before shipping:

1. **Golden reference** in `tests/golden/` was generated by `tests/generate_golden.py`
   on a fixed synthetic dataset (400 cells x 300 genes, 4 clusters, 17.4% density).
   It is produced by *this* package, so on its own it can only detect drift —
   never a shared error. See the R-parity gate below.

2. **R-parity gate** (`test_r_parity_gate`) is the actual accuracy check.
   `tests/r_reference.py` is an independent, dense, Numba-free transcription of
   celda's `src/DecontX.cpp` that shares no code with `decontx/`. Current
   correlation: **0.99995**. Before the R-parity fixes it was 0.9815, i.e. the
   suite was fully green while failing the standard stated in step 4.

3. **Regression tests** in `tests/test_regression.py` enforce:
   - `test_regression_*_bit_identical`: theta, phi, eta, contamination, decontX_counts
     must match golden to atol=1e-8. Note "bit-identical" is aspirational
     shorthand — float drift of ~1e-15 against a stored golden is normal and
     still passes.
   - `test_regression_correlation_gate`: contamination correlation with golden
     must be > 0.999 (drift detection)
   - `test_r_parity_gate`: contamination correlation with the R transcription
     must be > 0.999 (accuracy)
   - behavioral guards: multi-batch row order, per-batch seeds, batch named
     `"all"`, NaN batch labels, cluster-label round-trip, uns merge,
     log-transformed input rejection, shallow-data non-degeneracy, and
     convergence independence from `iter_loglik`

4. **After any change to fast_ops.py or model.py**:
   - Clear Numba cache: `find . -name "__pycache__" -type d -exec rm -rf {} +; find . -name "*.nbc" -delete; find . -name "*.nbi" -delete`
   - Run: `conda run -n scrna_v2 python -m pytest tests/test_core.py tests/test_regression.py -v -o addopts=""`
   - All 18 tests must pass

5. **When to regenerate golden**: only if the algorithm itself changes (not just
   performance). Re-run `tests/generate_golden.py`, then confirm
   `test_r_parity_gate` still passes — that gate, not the golden, is what
   establishes correctness.

6. **Multi-batch coverage** is now a real test (`test_multibatch_preserves_row_order`
   and friends) rather than a manual smoke test.

7. **Verify your install before trusting any result.**
   `conda run -n scrna_v2 python -c "import decontx; print(decontx.__file__)"`
   must print a path inside this repo. A stale editable `.pth` pointing at
   another checkout silently shadows the repo from every directory except the
   repo root — and because Numba has no bounds checking, running an older copy
   surfaces as heap corruption (`free(): invalid next size`, SIGSEGV) rather
   than a clean error. Reinstall with `pip install -e . --no-deps`.

## Architecture

- `decontx/core.py`: user-facing `decontx()` function, AnnData integration
- `decontx/model.py`: `DecontXModel.fit_transform()` — the EM loop
  - All input is converted to CSR (never densified during EM)
  - Pre-allocates `nc_data` (1D, length nnz), `phi_acc` (n_clusters, n_genes),
    `native_sums` (n_cells), and `global_acc` (n_genes); all reused each EM iteration
  - Calls `decontx_em_exact_sparse` (monolithic JIT: E-step + M-step)
  - Output is a sparse CSR matrix (same sparsity pattern as input)
- `decontx/fast_ops.py`: Numba JIT functions
  - `decontx_em_exact_sparse`: monolithic sparse EM (E+M in one JIT call)
    - E-step: parallel `prange` over cells, fills `nc_data` (CSR-aligned 1D)
    - M-step: serial scatter-add from `nc_data` into `phi_acc`, then normalize
  - `decontx_initialize_exact_sparse`: sparse-aware phi/eta initialization
  - `calculate_native_matrix_fast_sparse`: final decontaminated counts (CSR-aligned)
  - `decontx_log_likelihood_exact_sparse`: sparse log-likelihood
  - `decontx_em_exact`: original dense EM (legacy, not used in sparse path)
  - `precompile()`: opt-in JIT precompilation (lazy, not import-time)

## Optimization decisions and safety notes

1. **CSR-aligned nc_data**: `native_counts[j,g]` is 0 when `counts[j,g]==0` (the
   original code already guards with `if counts[j,g] > 0`). Keeping only the
   nonzero values in a 1D array aligned to CSR positions is bit-identical.
2. **Scatter-add M-step is parallel over clusters, and still deterministic.**
   `cell_order` (a stable argsort of `z`, computed once in `model.py`) groups
   cells by cluster and `cluster_starts` indexes into it, so thread `k` writes
   only `phi_acc[k]`. This avoids per-thread accumulator copies, which would
   cost `n_threads * n_clusters * n_genes`. Each cluster's cells are visited in
   a fixed order, so the float summation order does not depend on thread count
   — verified bit-identical at `NUMBA_NUM_THREADS` 1/4/16. Do not replace this
   with per-thread accumulators; it would be slower *and* non-reproducible.
3. **prange over cells (E-step only)**: each thread writes to disjoint slices of
   `nc_data` (cell j owns indptr[j]:indptr[j+1]). No shared writes. Bit-identical.
4. **eta from global_acc - phi_acc[k]**: `other_native = total_native - cluster_native`
   is algebraically identical to `np.sum(native_counts[other_mask, :], axis=0)`.
   Same values, same float64 arithmetic. Bit-identical.
5. **Pre-allocated EM buffers (`nc_data`, `phi_acc`, `native_sums`, `global_acc`)**:
   pure memory reuse, no arithmetic change.
6. **Lazy JIT compilation**: moved from import-time to first-use. No behavior change.
7. **Division-by-zero guard in eta**: if `total <= 0` (single-cluster edge case),
   falls back to uniform distribution. Bit-identical for normal multi-cluster data.
8. **Theta uses R's posterior mean** `(native + delta[0]) / (total + delta[0] + delta[1])`,
   matching `DecontX.cpp:119`. It previously used the posterior *mode* (`-1`/`-2`),
   which is not what celda does and which under-reported contamination by ~21%
   relative. The mode's denominator also went negative once delta fell below 1.0,
   inverting low-count cells (a fully-contaminated cell reporting 0%). The mean
   denominator is positive for any non-negative counts and positive delta, so
   the guard and the clamp were deleted rather than fixed. Do not reintroduce them.
9. **Cluster label remapping in DecontXModel**: `fit_transform` remaps arbitrary
   input `z` labels to a contiguous `1..n_clusters` range. This makes multi-batch
   processing safe when a batch contains only a subset of the global clusters.
10. **Optional `compute_log_likelihood`**: skipping the log-likelihood kernel removes
    periodic O(nnz) work. Default is `True` for backward compatibility. No accuracy
    impact because log-likelihood is used only for diagnostics/history.
11. **Convergence is checked every iteration**, as R does. It used to be sampled
    only every `iter_loglik`-th iteration, which overshot by up to 9 iterations
    and made the stopping point depend on a diagnostic setting. Decoupling it
    was previously reverted for breaking the golden — that was the golden being
    wrong, not the change. `test_convergence_independent_of_iter_loglik` now
    pins the correct behavior.

12. **Contamination is the E-step proportion** `(total - native) / total`
    (`DecontX.cpp:115`), not `1 - theta`. Theta is prior-shrunk, so `1 - theta`
    is pulled toward the delta prior.

13. **Decontaminated counts stay fractional.** R returns real-valued native
    counts and documents rounding as the caller's choice; rounding to int32
    zeroed ~8% of nonzero entries. This also means the output CSR no longer
    carries explicit zeros.

14. **Delta is fitted by Minka's fixed-point Dirichlet MLE**, matching
    `MCMCprecision::fit_dirichlet` (`DecontX.cpp:138`), with no clamp. It
    previously used method-of-moments with a `[0.1, 1000]` clamp; the fitted
    delta now matches the R reference to within 1e-6.
    `_digamma`/`_trigamma` are hand-rolled because `scipy.special` is not
    callable from Numba nopython mode — that is the reason MoM was there in the
    first place. They are validated against scipy to 1e-7 by
    `test_digamma_helpers_match_scipy`, and `fit_dirichlet_2d` returns the
    previous alpha unchanged on degenerate input rather than clamping.

15. **The only remaining difference from R is a one-E-step offset.** R reports
    contamination from the E-step at the start of its final iteration, so its
    reported contamination corresponds to a different E-step than its reported
    counts. decontx runs one more E-step with the converged parameters, keeping
    contamination consistent with the counts it returns (agreement: 5e-16).
    Align that step and the two implementations match to **7e-16** --
    `test_r_parity_is_exact_modulo_final_estep` pins this at 1e-10, which is a
    much stronger gate than the correlation threshold.

16. **Do not assert exact float equality on decontaminated counts.** They are
    float64 under `fastmath`, so drift of ~1e-14 across recompiles is normal.
    The regression tests use a 1e-8 tolerance.

17. **`dtype="float32"`** halves `counts_data`, `nc_data` and the CSR copy.
    Measured cost against the R reference: max abs error 2.4e-08 vs 7.2e-16 at
    float64, correlation still 1.000000000. Default stays float64. The kernels
    take their dtype from the arrays passed in, so do not hardcode
    `np.float64` in `fast_ops.py` — use `data.dtype`.

18. **`round_counts=True`** restores int32 output. Contamination is always
    computed from the *unrounded* native counts and in float64 regardless of
    the EM dtype — rounding is an output format, not an estimate change.

19. **Buffer reuse**: `calculate_native_matrix_fast_sparse` writes into the
    EM's existing `nc_data` buffer instead of allocating a second nnz-sized
    array. `all_integral` validates input without materializing temporaries
    (`np.allclose(data, np.round(data))` cost 13 ms and ~62 MB on a 3.9M-nnz
    matrix).
